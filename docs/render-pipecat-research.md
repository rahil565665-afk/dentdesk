# Render + Pipecat Free demo notes

Verified from official provider documentation on 2026-10-27. The selected architecture is one separate Render Free service per clinic, open-source Pipecat, and real-time browser audio. Twilio is optional settings only and remains disconnected. No secrets appear in this note.

## Render hosting and repository state

Render's API can create a Web Service from a repository and accept per-service environment settings. The source has now been pushed to a private GitHub repository. Clinic-agent provisioning uses that URL and the `agent/` root directory; Render repository access must be confirmed during service creation. Do not publish the source publicly. Sources: [Render create service](https://api-docs.render.com/reference/create-service), [Render web services](https://render.com/docs/web-services), [Render deploy docs](https://render.com/docs/deploys).

A read-only Render API check found one workspace, and the Render MCP later listed no services in that workspace. The Supabase project URL was matched to the user's active `Client Database` project. That database contains an older empty `appointments` table linked to `clients`; the DentDesk migrations must preserve those legacy tables and use a separate `receptionist_appointments` table. No Render service creation or deployment has yet been confirmed.

The official create-service reference currently documents `POST /v1/services` with `type: web_service`, `name`, `ownerId`, a repository URL without the branch, and a separate `branch`; it supports `autoDeployTrigger` values `commit`, `checksPass`, and `off`. The service tool exposes Node runtime, Free plan, region, build/start commands, environment variables, and explicit workspace targeting. The dashboard needs the private repo root, `main`, `singapore`, build `corepack enable && pnpm install --frozen-lockfile --prod=false && pnpm build && pnpm prune --prod`, and start `pnpm start`. Source: [Render API create service](https://api-docs.render.com/reference/create-service). This is an API shape note, not evidence that a service was created.

Render rejected the initial dashboard create request with HTTP 400 because the URL ended in `.git`; its validation response accepts GitHub URLs in `https://github.com/{namespace}/{repository}` form with the branch passed separately. The adapter now strips a trailing `.git` before posting, and the environment example uses the accepted URL form. No service was created by the rejected request. Source: [Render API create service](https://api-docs.render.com/reference/create-service).

Render's official instructions say Git-provider access is added from Account Settings → Account Security → Git Deployment Credentials → Add credential, which opens an authorization flow. Its private-repository deployment guide says private GitHub repositories require Render's GitHub App to be installed and the repository included in the app's access list. The user completed that connection. The next create attempt returned HTTP 402, requiring billing information; Render's service list remained empty, so no service was created. Sources: [Connect your Git provider](https://render.com/docs/git-provider), [Web Services](https://render.com/docs/web-services), [Render API](https://render.com/docs/api).

The application uses the per-variable environment endpoint for secret rotation and a service deploy endpoint afterward. It does not bulk-replace all variables for a one-key change and does not request secret values for display. Sources: [Update one env var](https://api-docs.render.com/reference/update-env-var), [Bulk environment variables](https://api-docs.render.com/reference/update-env-vars-for-service), [Trigger deploy](https://api-docs.render.com/reference/create-deploy).

Render Free services sleep after inactivity and can take time to wake. Use the free tier only for this non-production demo. The browser performs a bounded, visible health warm-up only after a user clicks **Start browser test**. A 25-second application message is sent only while that test call is connected. No external cron, scheduled request loop or hidden idle ping is used. A restart can interrupt an active call. Source: [Render Free limits](https://render.com/docs/free).

## Real-time audio design

The deployed agent uses `FastAPIWebsocketTransport` with protobuf serialization and the Pipecat JavaScript WebSocket client. An application-level lock limits the process to one active browser session. This supports bidirectional audio and state events for a controlled prototype, but it is not a claim of production-grade WebRTC media networking, NAT traversal, load-tested scaling or multi-client support. Sources: [Pipecat WebSocket transport](https://docs.pipecat.ai/api-reference/server/services/transport/websocket-server), [Render WebSockets](https://render.com/docs/websocket).

Pipecat's Gemini Live service provides real-time speech input/output and function calling. The default path uses Gemini native audio. Optional Cartesia TTS streams generated speech with a clinic voice ID; the agent requests text output from Gemini Live, so this path depends on selected-model text-modality support. Sources: [Pipecat Gemini Live](https://docs.pipecat.ai/api-reference/server/services/s2s/gemini-live), [Pipecat Cartesia TTS](https://docs.pipecat.ai/api-reference/server/services/tts/cartesia).

## Product and data boundaries

The dashboard and clinic agents use the same source repository but have distinct runtime roles. The dashboard has the protected Supabase secret and Render API key. Each agent has only its clinic's provider keys, tenant UUID and tenant-specific signing secret. Clinic configuration and call/appointment lifecycle metadata cross a short-lived signed bridge; the dashboard validates tenant scope before using Supabase. Agents do not persist audio, transcripts, caller identity or full conversations. Appointment records can include attendee name/email.

Clinic context supports a greeting, text knowledge field and structured FAQs. There is no uploaded-document extraction, embedding or vector search. Cal.com supports availability, booking, rescheduling and cancellation. Appointment changes require approval in the browser; existing booking changes also compare the supplied attendee email. The web human-transfer tool raises an escalation event and does not make a phone call.

The Twilio panel accepts account SID, auth token and E.164 number fields. Values can be saved to Render service configuration only; `TWILIO_ENABLED` stays false, and the application does not call Twilio, create webhooks, provision numbers or route calls.

Pipecat is open-source and does not require Pipecat Cloud. Gemini, Cartesia and Cal.com use their own provider accounts, credentials and quotas. Render Free is not an always-on production service. No healthcare-compliance certification is provided.

## External keep-alive probes (reviewed 2026-10-28)

Render says a Free web service spins down after 15 minutes without inbound traffic; HTTP requests and WebSocket messages count. An external monitor polling the dashboard's `/api/health` or an agent's `/health` before that timeout would therefore be expected to delay spin-down while requests keep arriving. Render documents external probes as a way to monitor uptime and diagnose incidents, not as a guarantee that a Free service will remain continuously available. Pings cannot prevent deploys, maintenance, network interruptions, or account usage limits. Sources: [Free services](https://render.com/docs/free), [Uptime best practices](https://render.com/docs/uptime-best-practices), [WebSockets](https://render.com/docs/websocket).

The Free allowance is 750 instance-hours per workspace per calendar month. A 10-minute keep-alive would keep each service running for nearly all of the month rather than allowing it to sleep. The dashboard plus one clinic agent kept awake for a 30-day month would use 1,440 instance-hours, exceeding the shared 750-hour allowance. This is not a sustainable way to keep the requested multi-service system always warm on Free. No external pinger has been configured; user-initiated wake remains in place until the user explicitly changes that requirement.
